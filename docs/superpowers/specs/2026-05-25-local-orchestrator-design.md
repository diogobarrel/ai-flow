# Design Spec: Local AI Dev Orchestrator

**Status:** Approved
**Date:** 2026-05-25
**Version:** 1.0.0
**Topic:** Local RAG + Fine-tuning for Dev Workflows

---

## 1. Vision & Goals

The **Local AI Dev Orchestrator** is a "Category 0" agent designed to sit at the top of the user's development workflow. It provides environment-aware intelligence, task routing, and autonomous execution of common development playbooks.

### Success Criteria:
- **Workflow Intuition:** The model instinctively knows when to use Claude Code vs. Gemini vs. Local Helpers.
- **Codebase Awareness:** The model can answer questions about the `/Dev` folder (project structures, tech stacks, logic locations).
- **Local-First Efficiency:** Most mechanical tasks are handled locally on an RTX 5070 Ti (16GB VRAM) using Ollama.
- **Extensibility:** The local knowledge and tools are exposed via MCP for use by cloud-based tools.

---

## 2. Architecture

The system is built in two major phases:

### Phase 1: Enhanced Open-Interpreter (The Terminal)
- **Engine:** Python-based wrapper around `open-interpreter`.
- **Model:** Fine-tuned `Qwen2.5-Coder-7B`.
- **Memory:** Local RAG using `LlamaIndex` + `ChromaDB`.
- **Interaction:** A chat-based terminal that can execute code, search the codebase, and follow playbooks.

### Phase 2: MCP Evolution (The Service)
- **Interface:** Model Context Protocol (MCP).
- **Integration:** Exposes local RAG tools and automation functions (bootstrapping, cleanup) as MCP tools.
- **Consumers:** Claude Code CLI, Gemini CLI, and potentially IDE extensions (Cursor/Continue).

---

## 3. Fine-tuning Strategy (The "Intuition")

### Dataset (Hybrid approach):
- **Synthetic (70%):** ~700 samples generated by Claude 3.5 Sonnet based on `WORKFLOW.md` and `playbooks/*.md`.
- **Golden Logs (30%):** ~300 samples from cleaned-up user session logs and shell history.

### Training Specs:
- **Base Model:** `Qwen2.5-Coder-7B-Instruct`.
- **Method:** 4-bit QLoRA via **Unsloth**.
- **Hardware Target:** RTX 5070 Ti (16GB VRAM).
- **Output:** GGUF format for Ollama integration.

---

## 4. Local RAG Strategy (The "Awareness")

### Tech Stack:
- **Orchestration:** LlamaIndex.
- **Chunking:** AST-based (Abstract Syntax Tree) for language-specific splitting.
- **Embeddings:** `nomic-embed-text` (via Ollama).
- **Vector DB:** ChromaDB (Local persistence).

### Search Capabilities:
- **Hybrid Search:** Vector (semantic) + BM25 (keyword) search.
- **Scope:** Recursive indexing of `C:\Users\santo\Dev` with exclusion lists (`node_modules`, `.git`).
- **Update Loop:** Incremental indexing triggered by file changes.

---

## 5. Implementation Roadmap

1. **Dataset Bootstrapping:** Generate synthetic data and collect golden logs.
2. **Fine-tuning Loop:** Train the 7B model using Unsloth and export to Ollama.
3. **RAG Prototype:** Build the LlamaIndex + ChromaDB pipeline for the `/Dev` folder.
4. **Interpreter Integration:** Update `open-interpreter/dev.py` to use the new model and RAG tools.
5. **MCP Transition:** Refactor tools into an MCP server for cross-tool synergy.
